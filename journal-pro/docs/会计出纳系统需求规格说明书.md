## 1. 修订背景与目标

用户（会计岗位）提出：现有系统业务过于简便，要求参考 GitHub 开源会计/出纳项目的优秀实践与行业真实痛点，形成需求文档并融入系统。本次修订目标：

1. 把「能记账的网页」升级为「符合会计内控与审计要求的业务系统」；
2. 覆盖出纳会计全流程任务活动：申请 → 审批 → 收付款 → 凭证 → 日记账 → 日结 → 银行对账 → 期末结账 → 报表 → 归档；
3. 保持前后端分离、数据库持久化、版本化迁移、可备份迁移、可发布上线；
4. 每项需求给出来源、优先级、验收标准、落地状态与系统模块。

## 3. 业界优秀实践提炼（可直接转化为需求）

### 3.1 记账内核 P0

1. **借贷平衡是约束不是约定**：TSI Ledger 在 post 时校验，`NUMERIC(18,4)` 不用浮点；OpenLedger 在同一数据库事务内校验「≥2 条分录且借方合计=贷方合计」；DoubleLedge 用延迟约束触发器在 COMMIT 时兜底。
2. **三分层模型**：凭证/单据 → 记账动作 → 借贷分录行；分录带科目、方向枚举、正金额、辅助维度（项目/往来单位）。
3. **金额精度军规**：整数最小单位（分）或 DECIMAL，禁止二进制浮点；每币种独立平衡。
4. **余额是派生值**：LedgerLoop 不存余额；`double_entry` 存物化余额但配定时校验任务。结论：流水表是真相，余额表是缓存，必须有重算/校验能力。

### 3.2 审计与内控 P0

5. **不可变账本**：OpenBooks 让应用数据库用户不持有 journal 表 UPDATE/DELETE 权限；FYZB 用「应用状态机 + 数据库触发器」双层防护。
6. **哈希链防篡改**：`hash_i = H(hash_{i-1} || payload_i)`，TSI Ledger `verify_audit` 全链校验；Ledger CLI 3.4 起也支持 `--hashes`。
7. **审计与业务同事务**：OpenLedger/FYZB 明确「业务、审计（及 Outbox）在同一事务提交」，避免账记了日志没记。
8. **更正只走冲销**：`reverse_transaction`/红字冲销生成反向分录，永不 UPDATE 历史记录。
9. **maker-checker 职责分离**：TSI Ledger 冲销手工录入凭证须第二人审批；ERPNext `Version` 记录操作人；FYZB 单人企业可开 SOLO 模式、多人团队默认严格分离。
10. **期间锁定对所有角色生效**：ERPNext Accounting Period 关闭后连 System Manager 也不能回溯修改。

### 3.3 对账自动化 P1

11. **六层骨架**：接入 → 归一化（保留原始字段）→ 匹配 → 例外人工队列 → 会计过账 → 报告审计。
12. **强证据优先，歧义不硬猜**：`recon-kit` 明确「唯一候选才算匹配，多于一个返回 Ambiguous 交人工」，拒绝金额容差；`@fin.cx/bankrec` 用加权信号评分并分「自动过账/人工队列/未匹配」三档；方向是硬过滤。
13. **错误自动匹配比未匹配更糟**（原文：A wrong auto-match is worse than an unmatched line），因为钱记错科目后对账依然平衡，下游永远抓不到。
14. **三道防重复/防漏**：对账单连续性（上期期末=下期期初）、导入幂等去重、重复交易指纹检测。
15. **未匹配项进挂账/调节表**，不静默丢弃；每笔匹配决策可回溯到规则、分数、操作人。

### 3.4 凭证与附件 P1

16. Draft→Submit→Cancel(→Amend) 生命周期，只有 Submit 产生财务影响；编号序列受控防断号重号。
17. 凭证模板/记账规则集中在统一控制器（ERPNext `AccountsController`），不散落在各业务单据。
18. **附件与凭证强关联**：Tilittaja 按凭证号自动匹配 PDF 收据；BeanDesk 分录可直接预览发票/回单；保留原始文件不删。
19. 结账后自动生成资产负债表、利润表、现金流量表、科目余额表（JinBooks/FYZB 标准功能清单）。

### 3.5 中式 ERP 的可借鉴点（jshERP / 华夏ERP）

- 模块范围明确：零售、采购、销售、仓库、**财务**、报表、基础资料、系统管理；财务侧含**总账、凭证、收入支出、预付款、资产折旧、往来对账**（4.6k stars，Apache-2.0，Java/SpringBoot + Vue，MySQL/Redis）；
- 权限细到「每个按钮和菜单」，配合多级审批与审核路径；
- 业务特色：预付款、其他收入支出、调拨/组装拆卸，适合小微贸易与批发；
- 工程取舍：单库单租户逻辑隔离、报表直接打业务库（小体量可接受）；无加密审计链，这是它相对欧美账本内核的短板，也是本系统要补的地方。

### 3.6 一线岗位的量化耗时（金蝶 2026 会计节披露，小微企业月单据 200–500 张）

| 苦活 | 传统做法 | 月耗时 | 系统化后 |
|---|---|---|---|
| 发票归集查验 | 手工核对电子税务局 | 8–15h | 1–2h |
| 银行流水对账 | 网银逐笔勾兑 | 6–10h | 1h |
| 凭证录入 | 一单一录 | 15–25h | 3–5h |
| 资产折旧计提 | Excel 公式 | 2–3h | 0.2h |
| 期末结转结账 | 手工过账 | 4–8h | 1–2h |
| **合计** |  | **35–61h** | 6–10h |

结论：功能优先级应按「月耗时 × 出错返工成本」排序，而不是按功能听起来是否高级。本轮据此优先做了折旧、结转、对账与迁移。

### 3.7 明确不照抄的做法

- Firefly III 的单侧拆分模型（收入多→一、支出一→多）不满足企业 n:n 记账；
- ERPNext 取消交易「无 1:1 单据↔GL 映射」在严格审计辖区有争议，本系统采用手工冲销凭证保留完整链条；
- AI 只能放在建议位，必须过本地规则引擎的确定性校验（借贷平衡、发票验真），不放在决策位。

|---|---|---|---|

## 6. 本轮系统改造清单（需求落地映射）

### 6.1 数据库（迁移 005_governance.sql）

- 新增 `invoices`（发票台账，唯一约束 invoice_no+kind 实现查重）、`budgets`（预算，唯一约束期间+科目+项目）；
- `audit_logs` 增加 `prev_hash` / `hash`；`vouchers` 增加 `reversal_of` / `approved_by` / `posted_by`；`docs` 增加 `approved_by`；`attachments` 增加 `entity_type` / `entity_id`；`bank_statements` 增加 `match_note`；
- 4 个不可变触发器：`trg_journal_immutable`、`trg_journal_no_delete`、`trg_vline_immutable`、`trg_vline_no_delete`；
- 启动时对历史审计日志一次性补建哈希链（幂等）。

### 6.2 后端 API（新增/改造）

- 内控：`/api/compliance`、`/api/audit/verify`、`/api/attachments/link`；
- 发票：`/api/invoices`（查重、状态流转、生成凭证、核销）；
- 预算：`/api/budgets` CRUD、`/api/reports/budget`；
- 账簿：`/api/reports/trialbalance`、`/api/reports/ledger`、`/api/reports/aging`、`/api/reports/cashflow`；
- 结账：`/api/closing/checklist`（8 项检查，阻断结账）；
- 对账：重写 `/api/statements/match`（唯一候选、无容差、匹配理由），新增 `/api/statements/continuity`；
- 凭证：新增 `reverse` 动作与红字冲销，审核/过账增加职责分离校验；单据结算增加预算拦截；
