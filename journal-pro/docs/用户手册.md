## 0. 快速上手（3 分钟）

1. 打开系统后默认进入**工作台**，顶部蓝色横幅下面是 7 张 KPI 卡，一眼看全局。
2. 记一笔账：**业务单据 → 新建单据**（或 **凭证管理 → 新增凭证** / **日记账 → 出纳直接登记**）。
3. 每天花 1 分钟：**日结核对** 填实际盘点数，看是否"账实相符"。
4. 每月最后一天：**期末结账** 页先看检查清单，全绿后点"结转损益"再"月末结账"。
5. 数据存在本机 `data/journal.db`；换电脑用 **系统管理 → 下载整站迁移包**。

> 操作员：右上角"操作员"输入框里填你的名字，所有操作都会记入审计日志，职责分离也按这个名字判断。

## 2. 业务单据（业务处理的起点）

**用途**：把"要花钱/收到钱"的业务先变成一张单据，走审批流，防止出纳直接付款没有依据。

### 2.1 四种单据

| 类型 | 场景 | 结算后会计分录 |
|---|---|---|
| 付款申请 | 买办公用品、付货款 | 借 费用/应付科目，贷 现金/银行 |
| 收款单 | 客户回款、收回借款 | 借 现金/银行，贷 应收/收入科目 |
| 备用金借款 | 员工出差借支 | 借 其他应收款，贷 现金/银行 |
| 费用报销 | 员工拿票报销 | 借 费用科目，贷 其他应收款（冲抵借款）或 现金/银行 |

### 2.2 生命周期

```
草稿 → 提交 → 已审批 → （出纳）办理收付款 → 已结算
              ↘ 驳回 → 已驳回（可改后重新提交）
```

- **草稿**：可以编辑（流水账页点"编辑"）、删除；
- **提交审批**：状态变为"待审批"；
- **审批通过/驳回**：审批人不能是申请人（职责分离，可在内控合规页关闭）；
- **办理收付款**：由出纳确认钱实际付/收了，系统自动生成凭证并登记日记账。报销单若关联了借款单，会自动核销借款。

### 2.3 注意事项

- 银行账户的单据必须选"结算方式"；
- 金额 > 0；
- 已结算的单据不能删，错账走**红字冲销**（见凭证管理）。

## 3. 发票管理

**用途**：进项/销项发票台账，防重复入账，发票直接生成凭证。

- **登记发票**：填发票号码、类型（进项/销项）、日期、往来单位、不含税金额、税额。同类型同发票号会被**自动查重拦截**。
- **生成凭证**：未入账发票点"生成凭证"——进项记"借 费用 / 借 进项税，贷 应付账款"；销项记"借 应收账款，贷 收入 / 贷 销项税"。
- **核销**：已入账发票完成收付款后点"核销"。
- 账龄分析（账簿与分析页）会统计未核销发票的 0-30/31-60/61-90/90+ 天分布。

---

## 4. 凭证管理

**用途**：借贷复式记账的核心。所有单据结算都会自动生成凭证，也可以手工录。

### 4.1 新增凭证

- 至少两条分录，**借贷必须平衡**，否则拒绝保存（底部实时显示差额）；
- 涉及"1001 库存现金 / 1002 银行存款"的分录，过账后自动出现在日记账；
- 可勾选"保存后直接过账"，但职责分离开启时会被要求先由他人审核。

### 4.2 状态流转

```
草稿 → 提交 → 已审核 → 过账（登记日记账）
                    ↘ 作废（仅未过账）
已过账 → 红字冲销（生成反向凭证，原凭证保留）
```

### 4.3 红字冲销（重要）

发现已过账凭证记错了？**不要删**（数据库也禁止删），点"红字冲销"：
- 系统生成一张方向相反的凭证并过账，两笔净额为零；
- 原凭证保留并标记"已冲销"，审计链完整可查；
- 冲销人不能是原制单人（职责分离）。

### 4.4 附件

已过账凭证可点"📎 附件"上传发票照片、回单 PDF，与凭证关联，随时下载。

## 5. 现金 / 银行日记账

**用途**：出纳的流水账，由已过账凭证自动生成，**逐笔结出余额**。

- 筛选：账户 / 月份 / 对账状态 / 日期段；
- **出纳直接登记**：临时收支不想走单据审批时用，后台自动生成凭证，保证账证相符；
- **对账状态**：未核对 / 已核对 / 已调节，可单笔改，也可"筛选结果全部标记已核对"；
- **导出**：Excel（多表工作簿）或 CSV；
- 收入支出同一行只会有一个方向（系统强制）。

## 6. 日结核对（日清月结）

**用途**：按日自动汇总本日收入、支出、结出余额；每天下班前盘点现金/核对银行，填"实际数"，系统自动判断是否账实相符。

- 绿色 ✓ = 账实相符；红色 ✗ = 有差异，请核查（同时会触发风险预警）；
- 只展示有发生额或填过盘点数的日期；
- 期末结账清单会检查"盘点差异"。

---

## 7. 银行对账

**用途**：把银行对账单和日记账勾对，出具余额调节表。

1. **导入对账单**：粘贴文本，每行 `日期,摘要,收入,支出`；
2. **自动勾对**：方向硬过滤 + 金额精确到分 + 日期 ±3 天；**唯一候选才自动匹配**，多个候选判为"歧义"交人工，绝不硬猜；
3. **余额调节表**：企业账面余额 / 对账单余额 + 四项未达账项 → 双方调节后余额，自动判断"调节相符"；
4. **连续性检查**：检测对账单日期大跨度缺口（可能漏导）。

---

## 8. 期末结账

**用途**：月末锁账。结账后该期间禁止新增/修改单据与凭证。

**结账检查清单**（结账前自动执行）：

| 类型 | 检查项 |
|---|---|
| 🚫 阻断 | 未过账凭证、未完成审批单据、借贷不平凭证 |
| ⚠ 提醒 | 未核对流水、未匹配银行流水、歧义匹配、未入账发票、折旧未计提、损益未结转、预算超支 |

**操作顺序建议**：处理完阻断项 → 点"结转损益" → 再点"月末结账"。错账需要改已结账期间？先"反结账"。

## 9. 固定资产

**用途**：资产卡片台账 + 直线法自动折旧。

- **新增资产**：原值、残值率、折旧月数、开始计提期间、折旧费用科目；
- 月折旧额 = 原值 ×（1 − 残值率）÷ 折旧月数；
- **计提本月折旧**：一键为所有在用资产生成"借 费用 / 贷 累计折旧"凭证并过账；重复计提会被拦截；
- 显示净值、剩余月数；折旧明细按月可查。

## 11. 风险预警

**用途**：给资金装"烟雾报警器"。系统按可量化规则实时扫描，按 高/中/低 三级排序。

### 11.1 内置规则（阈值可在页面底部调整）

| 级别 | 规则 | 默认阈值 |
|---|---|---|
| 高 | 现金余额低于安全线 | ¥2,000 |
| 高 | 银行存款低于安全线 | ¥10,000 |
| 高 | 现金安全月数不足 | 3 个月（低于一半算高危） |
| 高 | 预算超支 | 实际 > 预算 |
| 高 | 账实不符 | 盘点数 ≠ 账面余额 |
| 高 | 审计哈希链被破坏 | 校验失败 |
| 中 | 大额收支 | 单笔 ≥ ¥50,000 |
| 中 | 连续净流出 | 连续 3 天支出 > 收入 |
| 中 | 流水超期未核对 | 超过 7 天 |
| 中 | 银行流水未匹配 / 歧义匹配 | — |
| 中 | 预算接近上限 | 执行率 ≥ 80% |
| 中 | 重复凭证号 | — |
| 低 | 发票未入账 / 超期未核销 | 超 30 天 |

### 11.2 使用方式

- 页面顶部显示 高/中/低 数量统计；
- 每条预警有"类别 + 标题 + 明细"，点对应模块去处理；
- 底部"预警阈值设置"可改：现金/银行安全线、大额标准、安全月数、核对天数、预算提醒线、刷新频率。

## 16. 内控合规

- **账本不可变**：数据库触发器禁止修改/删除已登记日记账和已过账分录；
- **审计哈希链**：每条审计记录带前序哈希，篡改任何一条全链报红；
- **职责分离**：制单/审核/过账/冲销不能同一人（单人使用可在本页关闭）；
- **对账规则**：方向硬过滤、金额精确到分、歧义不自动匹配；
- 页面可一键校验审计链、切换治理开关。

## 20. 常见问题（FAQ）

**Q1：凭证记错了怎么办？**
未过账：直接作废。已过账：凭证管理 → 红字冲销。系统禁止删除已过账凭证。

**Q2：为什么我不能审批/过账自己的单据？**
职责分离开启中。换一个操作员操作，或在"内控合规"页关闭该开关（单人使用建议关闭）。

**Q3：结账时提示有阻断项？**
去"期末结账"页看检查清单，把 🚫 项清零（未过账凭证、未审批单据、借贷不平）。

**Q4：结余出现负数？**
日记账里会标红。检查是否漏记收入或重复记支出；也可能是期初余额没填。

**Q5：数据会丢吗？**
数据在 `data/journal.db`。建议每天"仅备份数据(JSON)"；换电脑用整站迁移包。

**Q6：下拉里没有我要的科目？**
基础资料 → 会计科目 → 新增，或在导入导出中心批量导入。

**Q7：双击启动.bat 没反应？**
① 确认在解压后的文件夹里（不是压缩包预览）；② 右键 zip → 属性 → 解除锁定；③ 双击"启动（诊断）.bat"看环境；④ 用 `start.bat`（内容相同，文件名更保险）。

**Q8：在线版和本地版数据同步吗？**
不同步。在线版数据在云端沙箱，本地版在本机浏览器/数据库。建议以本地版为主账，定期备份。

## 22. 往来账（客户 / 供应商）· V2.3 新增

**用途**：按往来单位归集全部业务：销项/进项发票（含未入账的）、收款、付款、其他往来分录，逐笔结出余额，可直接核对发票与收付款的对应关系。

- 进入「往来账」→ 先看到所有往来单位和未结发票金额 → 点"查看往来明细账"；
- 明细列：**日期、类型（销项发票/进项发票/收款/付款/确认收入等）、单据号（发票号）、凭证号、摘要、借方、贷方、余额**；

- 发票核对：状态"已入账"的发票行可直接点 **✓ 核销**；
- 可导出 **Word / Excel 往来对账单**（含明细账与汇总），发给对方盖章确认。

## 23. 财务报表（资产负债表 / 利润表 / 现金流量简表 / 勾稽核对）

**入口**：左侧「财务报表」→ 右上角选月份 → 资产负债表、利润表、现金流量表、勾稽核对全部按该期间重算。

### 23.1 资产负债表（时点报表）

- 口径：自账套启用起至所选期间末的累计余额 = 期初建账余额 + 全部已过账凭证；多次/跨年建账只取「≤ 所选期间的最近一次建账」，不会把几批期初相加；
- 负数余额自动重分类：**应收账款贷方 → 预收账款**、**应付账款借方 → 预付账款**、**应交税费借方 → 留抵进项税**（资产方，只计一次）。发生过重分类的行下方会有「↳」说明；
- 固定资产「原值 / 累计折旧」是展示行，合计按「固定资产净值」计入，不会重复加总；
- 除标准行外，科目表中新增的其他资产 / 负债 / 权益科目会**自动归集入表**，不会因新增科目导致报表不平；
- 权益区分「本年利润（已结转 4103）」「未结转损益」「利润分配」，做没做年结都看得清；
- 页头同时给出两个校验标记：**✓ 平衡** 和 **✓ 明细=合计**。

### 23.2 利润表（期间报表）

- **本期数**：仅所选月份当月；**本年累计数**：本年度 1 月 → 所选月，**按自然年度截断，不并入往年利润**；
- 完整结构：营业收入 → 营业成本 / 税金及附加 / 销售·管理·财务费用 → 营业利润 → 营业外收支 → 利润总额 → 所得税费用 → 净利润；
- 自动排除结转凭证（`is_closing`），期末结转不会把利润冲平；
- 新增的损益科目会自动归入对应行，未归类的进「其他损益（净额）」，保证净利润始终等于全部损益科目净额。

### 23.3 现金流量简表

- 按对方科目归集出纳日记账收支，展示「本期流入 / 本期流出」与「本年累计流入 / 流出 / 累计净额」；
- 接口 `/api/reports/cashflow` 支持 4 种口径：`all`（全账套）、`current`（当月）、`ytd`（本年累计）、`through`（自建账起至所选期间）。

### 23.4 三大勾稽关系

1. **资产 = 负债 + 所有者权益** —— 资产负债表恒等式；
2. **账套累计净利润（分年度汇总）= 资产负债表留存收益**（本年利润 + 利润分配 + 未结转损益）—— 因为利润表累计数按年截断、资产负债表留存的是累计值，核对时会把各年度净利分年汇总；
3. **出纳日记账现金流量净额 = 总账货币资金（1001+1002）变动** —— **独立双口径**：左边取日记账流水，右边取总账科目余额；不符通常说明有凭证未登记日记账，或日记账金额与凭证不一致。

任一不符会显示差额和针对性原因提示。

### 23.5 Excel 导出

点「导出报表 Excel（含编制口径）」，得到 5 个工作表：资产负债表（带重分类说明）、利润表、现金流量简表、勾稽关系核对、**编制口径**（说明每个数字的来源与口径）。

### 23.6 常见疑问

- **累计数为什么比我自己加的小？** 累计数只统计本年度；往年利润已体现在资产负债表的留存收益里，勾稽②会分年度汇总后比对。
- **勾稽②为什么不通过？** 多为有损益类凭证未过账，或凭证使用了非损益类科目。
- **跨年度怎么结账？** 年末在「期末结账 → 结转损益」把损益转入 4103；如需把本年利润转入 4104 利润分配，可手工做一张转账凭证，报表会自动识别，勾稽口径不受影响。
- **为什么报表里多了几行没见过的科目？** 那是科目表中新增的其他科目被自动归集入表，并标注「系统自动归集」，这是防止漏项的设计。

## 26. V2.7 架构重构（依赖方向 / 组合根 / 前端模块化）

### 26.1 先承认问题：AST 审计证据

用 AST 扫描全部 Python 模块（含函数内延迟 import）得到的真实依赖图：

| 症状 | 审计数据 |
|---|---|
| 循环依赖 | `server ↔ features`、`server ↔ analytics_api` 两处环 |
| 分层倒置 | `core/` 中 **11 处 `from server import`**（领域层反向依赖传输层） |
| 模块表 hack | `sys.modules["server"] = sys.modules[__name__]`，靠改写模块表掩盖 404 |
| 全局可变状态 | 模块级 `ROUTES = []`，所有控制器必须 import server 才能注册 |
| 上帝对象 | `server.py` 3002 行 / 134 函数 / 239 条 SQL / 最长函数 175 行 |
| 前端 | `app.js` 2155 行、75 个全局函数、0 个模块 |

所以上一版「加一层 `core/` 就叫分层」是不成立的：依赖方向没变，环还在。

### 26.2 重构手段（业界做法）

采用 **Clean Architecture 的依赖倒置 + 组合根（Composition Root）+ 绞杀者模式**，不推倒重来：

```
app/                        应用架构层
 ├─ routing.py              Router 实例（原全局 ROUTES）
 ├─ errors.py               共享 ApiError
 ├─ ports.py                LedgerPort 协议 + SqliteLedger（SQL 唯一收口处）
 ├─ container.py            Container + Facade 防腐层 + 端口工厂
 └─ bootstrap.py            组合根：唯一装配点，固定启动顺序
core/                       领域层（零 SQL、零 HTTP、零反向导入）
server.py / features.py / analytics_api.py
                            控制器层，只依赖 app.routing / app.facade
public/js/*.js              前端 8 个模块（工具 / 页面 / 交互 / 启动）
```

依赖规则（单向）：控制器 → `app` 抽象；领域层 → `LedgerPort` 抽象；`app` 本身**不导入任何上层模块**；只有组合根允许认识所有模块。

启动顺序被显式固定，这正是消环的关键：引导 Router → 导入 server（不再反向导入控制器）→ 把遗留函数注入 Container → 再导入 features / analytics_api 注册剩余路由 → 启动 HTTP。控制器通过 PEP 兼容的惰性绑定（防腐层）取遗留能力，测试可替换容器里的实现。

## 28. V2.10 税务中心（20 项功能，税额与税负率统一两位小数）

**入口**：左侧「税务 · V2.10 → 税务中心」，19 个工具卡。精度约定：**所有税额四舍五入到分，税率与税负率以百分比两位小数表示、比对与预警**。

### 28.1 增值税
- 销项 / 进项台账：按发票「税额÷不含税额」自动推断适用税率（13%、9%、6%、5%、3%、1%、0%）分组汇总；
- 进项认证：批量更新「待认证 / 已认证 / 不得抵扣」，仅已认证进项可抵扣；
- 增值税申报测算：应纳税额 = 销项 − 已认证进项 + 进项转出（不足抵扣形成留抵），同期间保存幂等更新，可记录已缴；
- 附加税费：城建税 / 教育费附加 / 地方教育附加，计税依据为当期应纳增值税。

### 28.2 税负率两点控制
- 增值税税负率 = 应纳税额 ÷ 会计口径营业收入（利润表），百分比两位小数；
- 在「税负率区间」设置下限 / 上限（如 2.00% ~ 3.50%），逐月自动判定：**偏低**（少缴风险）/ 区间内 / **偏高**（多缴）；同时给出企业所得税税负率与综合税负率。

### 28.3 企业所得税
- 季度预缴测算：累计利润 × 税率，小微分段自动判定（分段与税率可配）；
- 汇算清缴测算：会计利润 + 纳税调整项 = 应纳税所得额；业务招待费自动按「发生额 60%」与「收入 0.5%」孰低计算限额。

### 28.4 工资与个税
- 员工管理与专项附加扣除（子女教育 / 赡养老人 / 房贷利息 / 租房 / 继续教育，含月度限额提示）；
- 算薪：社保公积金费率可配，**个税按累计预扣法**（月数 = 本年已发薪月数；累计收入 − 5000×月数 − 累计专项扣除 − 累计专项附加，按预扣率表计算并减已预扣），跨月自动衔接。

### 28.5 其他
- 印花税计算器（税目表可配）；征期日历（每月 15 日、周末顺延）；税务申报工作台汇总本月各税种与征期倒计时。

## 29. V2.11 外部系统协同（开票 / 网银自动化）

### 29.1 先说边界：哪些能自动、哪些必须人工

| 层次 | 能否自动 | 说明 |
|---|---|---|
| 数据准备、格式校验、批量文件生成、结果回传、台账登记、对账 | **全自动** | 本系统完成 |
| 在电子税务局 / 网银上传文件、CA/UKey 签名、短信验证、资金授权 | **人工（必须）** | 系统只提供官方入口链接，不代登录 |
| 乐企数字开放平台 / 数电票接口、银企直联 / 开放银行 API | **可全自动，但需资质** | 需向主管税务机关申请乐企接入、与开户行签约银企直联；系统预留 API 模式配置 |

**明确不做**：模拟登录税局或网银、验证码/安全校验绕过、保存账号密码或 UKey PIN、代替授权人员操作资金。这类做法既违反网站条款，也无法稳定（CA、OTP、风控），对财务系统是重大风险。

### 29.2 开票侧（①-⑦）

1. 维护往来单位开票资料：纳税人识别号、发票抬头、地址电话、开户行账号；列表显示资料完整度；
2. 同步开票任务：从已结算收款单 / 待开票记录生成队列；
3. 开票前校验：缺抬头/税号、金额、税率异常，**导出前自动刷新最新单位资料**（补齐后无需重新同步）；
4. 导出**数电票批量开票模板 CSV**（购买方名称/税号/地址电话/开户行账号/项目名称/数量/单价/金额/税率/税额/备注，金额两位小数，UTF-8 BOM 可直接用 Excel 打开）；有问题资料的任务默认跳过并给出报告；
5. 在电子税务局由授权人员上传模板并开具（系统提供官方入口链接）；
6. 下载开票结果后回传：自动登记发票台账、**发票号查重**、更新任务状态、联动销项税额台账与往来账。

### 29.3 银行侧（⑧-⑬）

1. 同步付款任务：从已审批付款单生成队列，校验收款账号/开户行/金额；
2. 导出**银行批量付款文件**（模板可配：列映射、编码、分隔符；内置通用模板 + 工行对账单模板）；
3. 在网银由授权人员上传并完成 U盾/OTP 确认；
4. 回传付款结果（成功/失败/银行流水号）；
5. 多格式对账单导入：字段自动映射（日期/摘要/收入/支出），自动查重，接入「银行对账」自动匹配。

### 29.4 直连配置与合规

- 默认 `file` 模式（无需任何资质）；`api` 模式需企业自行申请资质并配置端点与证书路径；
- **系统不存储任何密码、令牌、UKey PIN**；配置写入时会拒绝 `password/token/secret/pin` 类字段（回归测试覆盖）；
- 所有导出/导入写审计日志，任务状态机：待导出 → 已导出 → 已完成 / 失败。
